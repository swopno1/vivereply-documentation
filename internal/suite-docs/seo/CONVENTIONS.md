# SEO Conventions

These are the technical SEO rules for the travel scaffold. Every client deployment inherits them.
If you have to break one for a client, record the reason in that client's `KEYWORD-MAP.md`.

The rules cover three kinds of discovery that share one foundation:

| Discipline | Goal | Primary lever |
|---|---|---|
| **SEO** | Rank in classic search results | Metadata, crawlability, internal links |
| **AEO** | Be the direct answer (featured snippet, voice, FAQ box) | Direct answer blocks, FAQPage schema |
| **GEO** | Be cited inside AI-generated answers | Self-contained passages, entity consistency, freshness |

All three depend on structured data and page content that machines can read without ambiguity.

## 1. Metadata

### 1.1 Every public route exports its own metadata

Every public route builds its metadata with `buildMetadata()` from `src/lib/seo/metadata.ts`:
static pages export a `metadata` object, and dynamic pages use `generateMetadata`. No public page
may rely on the root layout's metadata alone. If it does, it inherits the homepage canonical and
Google treats it as a duplicate of `/`.

```ts
// Static route: title/description come from src/content/en.ts → seo.faq
import { staticPageMetadata } from "@/lib/seo/pages";
import { SLUGS } from "@/content/slugs";

export const metadata = staticPageMetadata("faq", SLUGS.FAQ);
```

```ts
// Dynamic route: build from the entity's own data
export async function generateMetadata({ params }) {
  const destination = await getDestination((await params).slug);
  return buildMetadata({
    path: SLUGS.destination(destination.slug),
    title: seoTemplate("destinationTitle", { destination: destination.name }),
    description: seoTemplate("destinationDescription", { … }),
    image: { url: destination.heroImage, alt: "…" },
  });
}
```

`buildMetadata()` (`src/lib/seo/metadata.ts`) is the only place that assembles titles,
canonicals, Open Graph, Twitter cards, hreflang and robots directives. Pages supply
**content**, not **structure**. Client-component pages (`/contact`, `/gallery`) declare
metadata in a sibling `layout.tsx`.

Next.js streams `generateMetadata` output into `<body>` for regular browsers on dynamic
routes. `next.config.ts → htmlLimitedBots` makes crawlers and link-preview bots receive it in
`<head>`, which is where Bing, AI crawlers and social previews look.

### 1.2 Title format

```text
[Page-specific title] | [Property Name] — [Location]
```

- Maximum **60 characters**. Google truncates longer titles in results.
- The page's primary keyword appears within the **first 30 characters**.
- The suffix comes from `brand.config.ts` (`name` and `property.locationLabel`).
- If the full title would go over 60 characters, `buildMetadata()` drops the parts in this order:
  1. Drop `— [Location]`: `[Page title] | [Property Name]`
  2. Drop the whole suffix: `[Page title]`
- The homepage is the one exception. Its title is `[Property Name] — [Location]` followed by a short value proposition.
- Titles are unique across routes. `scripts/check-seo-metadata.ts` fails the build if two routes share a title.

### 1.3 Description format

- One sentence, **140–160 characters**.
- Contains the value proposition **and** a call to action ("Book direct", "See directions", "Read the guide").
- No keyword stuffing. A keyword appears at most once.
- No duplicates across routes. Dynamic routes (destinations, blog posts, attractions) build the
  description from the entity's own fields, never from a shared default.

### 1.4 Canonical URL

- Every page sets `alternates.canonical` to its own **absolute** URL.
- Canonicals are **self-referencing only**. A page never canonicalizes to a different page.
- Canonical URLs have no trailing slash, no query string, and no fragment.
- Absolute URLs are always built from `https://${brand.domain}`, never hardcoded.

### 1.5 Open Graph

| Property | Value |
|---|---|
| `og:title` | Same as `<title>` |
| `og:description` | Same as meta description |
| `og:image` | 1200×630, generated by `src/app/opengraph-image.tsx` unless the entity has its own hero image |
| `og:type` | `website` for static pages; `article` for blog posts |
| `og:locale` | `en_US`, with `og:locale:alternate` = `bn_BD` |
| `og:site_name` | `brand.config.ts` → `name` |
| `og:url` | Same as the canonical |

### 1.6 Twitter Card

| Property | Value |
|---|---|
| `twitter:card` | `summary_large_image` |
| `twitter:title` | Same as `og:title` |
| `twitter:description` | Same as `og:description` |
| `twitter:image` | Same as `og:image` |

## 2. Heading Hierarchy

- Exactly **one `<h1>`** per page, and it names the page's subject.
- Sections use `<h2>`. Subsections use `<h3>`. **Never skip a level**, for example `<h2>` straight to `<h4>`.
- Headings describe the content; they are not decoration.
  - ✅ "Where is Client Resort & Spa located?"
  - ❌ "Location"
- Where the content answers a question, phrase the heading as that question. This matches voice
  queries and "People also ask" boxes.
- Decorative labels such as eyebrows, badges and kickers are `<span>` or `<p>`, never headings.
- Components shared across pages (headers, footers, widgets) never render an `<h1>`.

## 3. URL Conventions

- Slugs are lowercase and hyphenated: `/destinations/sitakunda-eco-park`.
- No stop words: `sitakunda-eco-park`, not `the-sitakunda-eco-park`.
- No query parameters on content pages. Pagination and the `?lang=bn` hreflang alternate (§6) are the only exceptions.
- No trailing slash. `next.config.ts` keeps `trailingSlash: false`, so Next.js 308-redirects `/faq/` to `/faq`.
- Every route and slug builder lives in `src/content/slugs.ts`, the single source of truth. Components
  use `SLUGS.FAQ` or `SLUGS.destination(slug)`, never string literals.
- Bengali slugs are not used. Language is a client-side toggle, so URLs stay English.
- A published slug is never changed. If it must change, add a permanent redirect in `next.config.ts` in the same commit.

## 4. Robots Conventions

### 4.1 robots.txt (`src/app/robots.ts`)

Production output:

```text
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /api/
Disallow: /style-guide
Disallow: /booking/confirmation/

Sitemap: https://[domain]/sitemap.xml
```

- **Never block CSS or JS** (`/_next/`). Google renders pages before indexing, and blocking
  render-critical assets makes it index a broken layout.
- `/book/[roomId]` is **not** disallowed. It is a crawlable conversion page.
- `/booking/confirmation/*` is disallowed because those pages contain per-guest data.

### 4.2 Meta robots

- Public pages emit `<meta name="robots" content="index, follow">`.
- Utility pages (booking confirmation, blog submission success) emit `noindex, follow`. Robots.txt
  also blocks the confirmation pages as belt and braces.
- `/admin/*` emits `noindex, nofollow`.

## 5. Environment-Aware Behavior

`NEXT_PUBLIC_ENV` alone controls indexing. `src/lib/seo/env.ts` exports `isIndexable()`, and it is
the only function that reads that variable for SEO purposes.

| Behavior | Staging (`NEXT_PUBLIC_ENV !== "production"`) | Production (`NEXT_PUBLIC_ENV === "production"`) |
|---|---|---|
| `robots.txt` | `User-agent: *` / `Disallow: /` | Rules in §4.1 |
| Meta robots | `noindex, nofollow` on every page | `index, follow` (except utility pages) |
| Sitemap link in robots.txt | Omitted | Present |
| JSON-LD | Rendered, so it can be validated on staging | Rendered |

Rules:

- The default is **not indexable**. A deploy that forgets to set `NEXT_PUBLIC_ENV` can never leak a staging site into Google.
- `NEXT_PUBLIC_*` values are inlined at build time, so switching environments requires a **rebuild**, not just a restart.
- Before a production launch, run the "Go-live" section of `LOCAL-SEO-CHECKLIST.md`.

## 6. Multilingual Conventions (English / Bengali)

- `<html lang="en">` is server-rendered. `LanguageContext.tsx` switches it to `lang="bn"` on the client when Bengali is active.
- Hreflang is emitted through `alternates.languages` in `buildMetadata()`:

  ```ts
  languages: {
    "en": "https://[domain]/page",
    "bn-BD": "https://[domain]/page?lang=bn",
    "x-default": "https://[domain]/page",
  }
  ```

- Use `bn-BD`, **never** bare `bn`, for the Bengali alternate.
- `?lang=bn` selects Bengali when the page loads in the browser.
- **Blog posts** with Bengali content are rendered in Bengali **on the server** at `?lang=bn`.
  That URL self-canonicalizes and uses `metaTitleBn`/`metaDescriptionBn`, so the pair is fully
  reciprocal. Posts without Bengali emit no `bn-BD` alternate.
- **Known limitation (other pages):** Bengali is rendered on the client, so the server HTML at
  `?lang=bn` is English. The canonical of `?lang=bn` also points to the English URL, and Google
  may ignore an alternate that canonicalizes elsewhere. `SEO-STRATEGY.md` §8 has the `/bn/`
  path-routing migration that fixes both issues.
- Every public string in `en.ts` has a counterpart in `bn.ts`. Run `pnpm exec tsx scripts/check-i18n-parity.ts`.

## 7. Structured Data Conventions

`SCHEMA-REFERENCE.md` is the full reference. The rules in brief:

- One generator per schema type in `src/lib/structured-data/`, re-exported from `index.ts`.
- **No dead generators.** A generator that no page calls is deleted.
- Every entity has a stable `@id`: `https://[domain]/#organization`, `https://[domain]/#lodging`,
  `https://[domain]/destinations/[slug]#lodging`.
- Related entities go in one `@graph` and reference each other by `@id`.
- Every value comes from `brand.config.ts`, `src/content/`, or the database. Nothing is invented.
  If a value is unknown (no Wikidata entry, no TripAdvisor listing), the property is **omitted**, not filled with a placeholder.
- `AggregateRating` and `Review` markup is only emitted from real review data in `GoogleReviewCache`,
  and only when that data exists. Hardcoded ratings are forbidden.
- JSON-LD is serialized with `serializeJsonLd()`, which escapes `<` so content cannot close the `<script>` tag.

## 8. Content Conventions (summary)

`CONTENT-GUIDE.md` and `AEO-GEO-GUIDE.md` have the full rules.

- Key pages open with a **direct answer block**: a question `<h2>`, a 10–15 word `<strong>`
  answer, then 40–60 words of context.
- Paragraphs stay under 60 words, and each one makes sense on its own.
- Every image has alt text naming the property or place, the location, and the subject.
- Places are always called by their canonical name from `src/content/entities.ts`.

## 9. Verification Commands

Run the server-backed checks against a **production** build
(`NEXT_PUBLIC_ENV=production pnpm build && NEXT_PUBLIC_ENV=production pnpm start`).

| Check | Command |
|---|---|
| Build + types | `pnpm build` |
| Lint | `pnpm lint` |
| en/bn parity | `pnpm exec tsx scripts/check-i18n-parity.ts` |
| FAQ answer length + Bengali present | `pnpm exec tsx scripts/check-faq.ts` |
| Titles, descriptions, canonicals, hreflang, OG/Twitter, h1 count, heading levels, alt text, uniqueness | `pnpm exec tsx scripts/check-seo-metadata.ts` |
| Broken links, redirecting links, orphans, internal-linking rules | `pnpm exec tsx scripts/check-internal-links.ts` |
| NAP consistency (visible + JSON-LD) | `pnpm exec tsx scripts/check-nap.ts` |
| JSON-LD nodes on a page | `python3 scripts/extract-jsonld.py http://localhost:3000/<path>` |
| Schema validity | Google Rich Results Test on the rendered page (`SCHEMA-REFERENCE.md` §15) |
